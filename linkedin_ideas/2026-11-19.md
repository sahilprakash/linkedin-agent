That one DAX formula that turns a slow report into lightning.

I was stuck on a report that recalculated every time I filtered by date. The culprit? A CALCULATE that pulled all rows from a massive fact table.
I rewrote it to use a SELECTCOLUMNS filter and added a SUMX over a pre‑filtered virtual table.

Key steps:

2. Use SELECTCOLUMNS to limit columns.

## Idea 5 — Power BI & DAX
**Topic:** Calculated Columns vs Measures: When to Pick Each

**Hook:** Confused on columns vs measures? The rule of thumb is simple.

**Full Draft:**

Confused on columns vs measures? The rule of thumb is simple.

Calculated columns run once per row during data load, so they’re great for static transformations like splitting a full name. Measures run on demand and are perfect for dynamic calculations that depend on filters, like a running total.

If you need a value that stays the same every time the data model refreshes, use a calculated column. If the value must change with slicers or visuals, go for a measure.

I once used a calculated column for a year‑over‑year growth metric, which bloated the model and slowed refreshes. Switching to a measure fixed the issue.

Next time you’re designing a model, ask: Is this value static or dynamic?
