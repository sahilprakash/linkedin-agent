**Hook:** Write transformations once, run them everywhere in Fabric.

**Full Draft:**

Write transformations once, run them everywhere in Fabric.

I approached Fabric dataflows the way I’d write dbt models: each step has a clear input, output, and test. By adding Fabric’s built‑in assertions (row count, null checks) right after each transformation, the pipeline self‑validates before moving to the next layer.

The result? A CI‑like experience where a failed assertion stops the downstream gold lakehouse, preventing bad data from reaching dashboards. Plus, the same .sql scripts live in Git, so version control is seamless.

If you’re still using ad‑hoc queries in Power Query, consider treating each dataflow as a modular model.
