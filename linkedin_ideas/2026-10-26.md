## Idea 1 — Power BI & DAX
**Topic:** Master YTD Calculations with CALCULATE Trick

**Hook:** Stop guessing why your YTD line is off.

**Full Draft:**

Stop guessing why your YTD line is off.

Last month I spent an hour fixing a YTD measure that kept dropping the latest month. The fix? A single CALCULATE tweak that respects the current filter context.

```DAX
YTD Sales =
CALCULATE(
    TOTALYTD([Sales], 'Date'[Date]),
    ALLSELECTED('Date')
)
```

By wrapping TOTALYTD with ALLSELECTED we keep the slicer choices but still get a true year‑to‑date view. No more manual date tables or hard‑coded boundaries.

Try swapping your YTD logic with this pattern and watch the numbers line up instantly.

## Idea 2 — Power BI & DAX
**Topic:** When to Use Measures Over Calculated Columns

**Hook:** Your report is slow—here’s the hidden culprit.

**Full Draft:**

Your report is slow—here’s the hidden culprit.

I once inherited a dashboard with dozens of calculated columns that recomputed on every refresh. The result? A 30‑minute load time that scared off stakeholders.

The rule of thumb: use measures for anything that can be aggregated on the fly. Calculated columns lock values into the data model, inflating size and slowing queries.

Swap a column like:
```DAX
ProfitCol = [Revenue] - [Cost]
```
with a measure:
```DAX
Profit = SUM('Fact'[Revenue]) - SUM('Fact'[Cost])
```

You’ll see memory usage drop and visuals respond instantly.

Have you transformed a column into a measure recently? Share the impact!

**Why it works:** _It highlights a clear before‑after performance win, encouraging comments about personal experiences._

## Idea 3 — Power BI & DAX
**Topic:** Context Transition Made Simple for Better Visuals

**Hook:** Ever wonder why a filter behaves oddly?

**Full Draft:**

Ever wonder why a filter behaves oddly?

I was debugging a chart where selecting a product stopped showing its sales. The root cause? A misplaced CALCULATE that forced a context transition.

Remember: CALCULATE swaps the current row context for filter context. If you need a row‑level value inside an aggregation, wrap it with VALUES or SELECTEDVALUE.

Example fix:
```DAX
Product Sales =
CALCULATE(
    SUM('Sales'[Amount]),
    VALUES('Product'[ID])
)
```
Now the visual respects the product slicer and the numbers line up.

Try this pattern on any visual that seems to ignore your filters.

Which visual gave you the biggest surprise after applying context transition?
