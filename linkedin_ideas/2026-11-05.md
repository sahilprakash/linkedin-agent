The moment I froze on a DAX interview question.

During a senior BI role interview, the panel asked me to write a measure that shows month‑over‑month growth while ignoring a slicer on “Region”.  My mind raced – I knew CALCULATE was the key, but the exact syntax slipped away.  I took a breath, wrote:

```
MoM Growth =
    CALCULATE(
        DIVIDE([Sales], PREVIOUSMONTH([Date])) - 1,
        ALLSELECTED('Region')
    )
```

The panel smiled and asked why I used ALLSELECTED instead of ALL.  I explained that ALLSELECTED respects other user filters while removing only the Region filter – exactly the context they wanted.

Lesson learned: practice the “why” behind each function, not just the syntax.  Next time, I’ll walk the board through my thought process before typing the code.

Your report loads slower than a coffee break?

I recently trimmed a 200‑MB model down to 45 MB and cut refresh time from 3 minutes to under 30 seconds.  Here’s the quick checklist I used:

1️⃣ Remove unused columns – even hidden ones still consume memory.
2️⃣ Switch calculated columns that don’t need row context to measures.
3️⃣ Enable “Storage mode – Dual” for tables used in both DirectQuery and Import.
4️⃣ Collapse many‑to‑many relationships into a single bridge table.
5️⃣ Turn on “Auto date/time” only for the tables that truly need it.

Apply these steps one by one, and you’ll see an immediate performance jump without sacrificing functionality.

## Idea 5 — Power BI & DAX
**Topic:** CALCULATE Tricks That Change Context Instantly

**Hook:** One CALCULATE tweak saved me 30% query time.

**Full Draft:**

One CALCULATE tweak saved me 30% query time.

I was troubleshooting a sales variance measure that kept recalculating over the entire fact table, even when a product slicer was applied.  The fix was simple: wrap the filter in VALUES inside CALCULATE.

```
Sales Variance =
    CALCULATE(
        [Total Sales] - [Target Sales],
        VALUES('Product'[ProductKey])
    )
```

VALUES forces the engine to treat the product filter as a single‑row context, preventing a full table scan.  The measure now runs in a fraction of the time, and the visual updates instantly.

Try swapping ALL for VALUES when you need the filter but not the full context.
