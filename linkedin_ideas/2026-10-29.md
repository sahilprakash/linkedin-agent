My answer: use a simple SUMX over the table with the same expression in both places. **Topic:** Speed Up Your Power BI Refreshes Instantly

Your reports are slow because of one tiny setting.

I once inherited a dashboard that refreshed in 12 minutes. The culprit? The default DirectQuery storage mode was set to “Import” for a table that never needed to be cached.

Switching that table to DirectQuery and enabling “Query reduction” cut the refresh time to under two minutes. The second tweak was to set the model’s aggregation tables, letting Power BI answer high‑level queries without hitting the source each time.

Finally, I added a simple incremental refresh policy on the large fact table – only the last 30 days reload, the rest stays untouched.

## Idea 5 — Power BI & DAX
**Topic:** CALCULATE Tricks You’ve Never Heard Before

**Hook:** A single CALCULATE tweak can flip your totals.

**Full Draft:**

A single CALCULATE tweak can flip your totals.

I was asked to build a month‑to‑date sales metric that ignored returns. The usual approach was to add a filter inside CALCULATE, but the model already had a “ReturnFlag” column that was being overwritten by row context.

The solution: wrap the filter inside VALUES() to force a single‑value context, then apply it with CALCULATE. The formula looks like this:

```
MTD Sales = CALCULATE(SUM(Sales[Amount]), VALUES(Sales[Date]), Sales[ReturnFlag] = FALSE)
```

Using VALUES() broke the unwanted context transition and gave the correct result without extra tables.

Do you have a CALCULATE pattern that saved you hours of debugging? Let’s hear it.
