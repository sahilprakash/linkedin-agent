## Idea 2 — Power BI & DAX
**Topic:** When to Use Measures vs Calculated Columns

**Hook:** Columns vs measures: the debate ends here.

**Full Draft:**

Columns vs measures: the debate ends here.

Early in my career I added a calculated column for every business rule, thinking it would make the model easier to read. The file grew to 2 GB, refresh times doubled, and my teammates complained about sluggishness.

The rule of thumb I now follow: if the value changes with filters, use a measure; if it is static per row, a column is fine. Measures stay in memory only when needed, while columns occupy storage and slow down load.

I rewrote three heavy columns into measures and cut the dataset size by 40 %. Your model will feel lighter and more responsive. What’s the most costly column you’ve ever removed? Comment your story.

## Idea 3 — Power BI & DAX
**Topic:** Speed‑Up Large Datasets with Query Reduction

**Hook:** Your report is slow—fix it in three steps.

**Full Draft:**

Your report is slow—fix it in three steps.

Step 1: Turn off auto‑date/time and set a proper date table. This removes hidden tables that double the query load.

Step 2: Replace expensive calculated columns with measures that use VAR to store intermediate results. VAR keeps the engine from recomputing the same expression for every row.

Step 3: Use KEEPFILTERS inside CALCULATE to avoid full‑table scans when you need to respect existing filters.

I applied this checklist to a sales dashboard with 12 million rows; refresh time dropped from 28 seconds to 6 seconds. Try it on your next project and watch the difference.

**Hook:** Turn raw data into gold with a three‑layer lakehouse.

**Full Draft:**

Turn raw data into gold with a three‑layer lakehouse.

In Fabric, I set up a classic medallion architecture: Bronze captures the raw ingest, Silver cleanses and standardizes, and Gold serves business‑ready tables. Using OneLake as the storage backbone, each layer lives in its own folder and is exposed through a semantic model.

The key is to let dataflows handle Bronze‑to‑Silver transformations, then use Fabric pipelines to materialize Gold tables with incremental refresh. This separation keeps lineage clear and lets analysts query only the polished view, while engineers focus on data quality.

The result? A single‑click Power BI report that reads from the Gold layer and refreshes in under two minutes, even with terabytes behind it. Have you tried a medallion pattern in Fabric? What hurdles did you hit?
